# 无线调试连接（Android 11+ 配对）— 需求分析与技术方案

> 版本：v1.0　日期：2026-11-16　状态：方案评审
> 适用代码：`QtScrcpy-dev`（Qt 5.15.2 / MSVC 2019 x64，内置 platform-tools 33.0.2）

---

## 1. 问题背景

### 1.1 用户视角的异常

用户在 Android 11 及以上的「开发者选项 → 无线调试」中拿到的是**一组 IP:配对端口 + 6 位配对码**，标准流程为：

```
① adb pair  192.168.x.x:<配对端口>   <6 位配对码>     # 首次配对，端口每次随机
② adb connect 192.168.x.x:<连接端口>                  # 配对成功后连接，端口与①不同
```

而本工程当前的"无线连接"走的是 Android 10 及以下的**老路子**：

```
插 USB → 更新设备 → 获取 IP → adb -s <serial> tcpip 5555 → adb connect <ip>:5555
```

两者不兼容，表现为：

| 现象 | 根因 |
|---|---|
| 不插 USB 就"无线连接"一直失败 | 设备 `adbd` 未监听 TCP 时 `connect` 必然失败；而开启监听只能靠 USB 下 `adb tcpip` |
| 按无线调试界面的端口填进去仍失败 | 该端口是**配对端口 / 连接端口**，不是 `tcpip 5555` 端口；且必须先完成 `pair` 授权 |
| 部分机型（Android 11+ 定制 ROM）`tcpip 5555` 无效 | 系统默认关闭 `tcpip` 或强制走配对流程 |
| 点击后长时间无任何提示，最终只看到 "adb run" | `adb connect` 失败**退出码仍为 0**，且失败文案被丢弃（见 §1.3-E） |

### 1.2 现状代码事实（已核对）

| 项 | 事实 | 位置 |
|---|---|---|
| 配对实现 | **零实现**。全仓库搜 `adb pair` / `_adb-tls-pairing` / `mdns` → 0 命中 | — |
| 内置 adb | platform-tools **33.0.2**（`adb pair` 需 ≥ 30.0.0，**满足**） | `QtScrcpyCore/src/third_party/adb/win/adb.exe` |
| 无线连接按钮 | 仅拼 `connect <ip>:<port>`，serial 传空（全局命令） | `ui/dialog.cpp:1198-1237` |
| 启动 adbd | `adb -s <serial> tcpip 5555`（强依赖 USB） | `ui/dialog.cpp:1239-1250` |
| 无线断开 | `adb disconnect <ip>`——**漏了端口**，与连接不对称 | `ui/dialog.cpp:1464-1475` |
| 一键 WIFI 连接 | 用 `delayMs()` 阻塞串起 8 步，失败点全部静默返回 | `ui/dialog.cpp:1597-1632` |
| adb 执行层 | 异步 `execute()`，**无超时、无 waitForFinished、无 stdin 写通道** | `include/adbprocess.h:26-44`、`src/adb/adbprocessimpl.cpp:117-128` |
| 设备识别 | `adb devices` 解析按 tab 切分、第 2 字段为 `device` 即在线，`IP:port` 形态天然支持 | `src/adb/adbprocessimpl.cpp:151-170` |
| 历史持久化 | 仅 `IpHistory` / `PortHistory` 两个独立列表（各 10 条，存 `userdata.ini` 根节点），**不存 ip:port 组合、无配对端口记录** | `util/config.cpp:152-159, 560-622` |
| UI 控件 | `wirelessGroupBox`：IP 可编辑下拉、端口可编辑下拉（placeholder 5555）、连接/断开两个按钮；**无配对码输入、无发现列表、无状态指示** | `ui/dialog.ui:1262-1384` |
| i18n | 仅有「无线连接/无线断开/一键WIFI连接」，**无"配对/配对码"条目** | `res/i18n/zh_CN.ts:534-547` |

### 1.3 实测得到的三条关键约束（决定方案形态）

用本工程内置 adb 33.0.2 对不可达地址实测：

| 命令 | 耗时 | 退出码 | 输出 |
|---|---|---|---|
| `adb connect 192.168.1.250:39999` | **21 s** | **0**（失败也是 0！） | `cannot connect to 192.168.1.250:39999: 由于连接方在一段时间后没有正确答复…(10060)` |
| `adb pair 192.168.1.250:39998 123456` | **21 s** | **1** | `error: protocol fault (couldn't read status message): No error` |
| `adb pair`（无参数） | 即时 | 1 | `usage: adb pair HOST[:PORT] [PAIRING CODE]` |
| `adb mdns services` | 即时 | 0 | `List of discovered mdns services` + 每条 `服务名 \t 服务类型 \t IP:端口` |
| `adb version` | 即时 | 0 | `1.0.41 / 33.0.2-8557947` |

结论：

- **A. 配对码可以命令行传参**（`adb pair HOST[:PORT] CODE`），无需扩展 QProcess 的 stdin 写通道——方案可行性确认；
- **B. `connect` 的成败只能解析文本**（`connected to` / `already connected to` = 成功；`cannot connect to` / `failed to connect` = 失败），不能看退出码；
- **C. 不可达时黑箱等待 21 秒**，必须有"进行中"状态 + 可取消 + 兜底超时，否则用户以为卡死。

## 2. 功能目标与预期行为

### 2.1 目标

1. **免 USB 完成首次连接**：仅凭「IP + 配对端口 + 配对码 + 连接端口」四要素即可在 Android 11+ 上建立无线调试连接；
2. **自动发现**：同一局域网内自动列出 `_adb-tls-pairing._tcp` / `_adb-tls-connect._tcp` 设备，免手抄 IP 与端口；
3. **全程可见**：每一步（发现→配对→连接）都有明确状态、耗时提示、失败原因与下一步建议；
4. **兼容旧流程**：Android 10 及以下仍可用 USB + `tcpip 5555` 方式，两者共存不冲突；
5. **可复连**：已配对设备重连只需一次点击（端口从历史/mDNS 自动带出）。

### 2.2 预期行为（用户视角）

```
[无线调试] 区域
 IP: [192.168.1.20 ▾]  连接端口: [37123 ▾]  配对端口: [40567 ▾]  配对码: [______]  [配对并连接] [断开]
                                    ▲ 也可从「发现设备」下拉一键带出全部字段
状态: ● 正在配对 192.168.1.20:40567 …（通常 1–3 秒，超时 30 秒）
```

| 步骤 | 触发 | 成功表现 | 失败表现 |
|---|---|---|---|
| 发现 | 打开无线区域 / 点「刷新发现」 | 列出 `设备型号 IP:端口`，点击自动填充四要素 | 空列表 + 提示"未发现设备：请确认手机与电脑同一局域网、无线调试已开启" |
| 配对 | 点「配对并连接」 | `配对成功` → 自动进入连接步骤 | 弹窗区分：配对码错误 / 端口已失效 / 网络不可达 / adb 版本过低 |
| 连接 | 配对成功自动执行 | 状态"已连接 IP:port"，设备出现在设备列表，可直接启动服务投屏 | 提示"配对成功但连接失败"，并给出「重试连接」按钮 |
| 断开 | 点「断开」 | `adb disconnect IP:port` 成功，设备从列表消失 | 提示失败原因；若设备已离线按成功处理 |

### 2.3 明确不做（本期范围外）

- 二维码扫码配对（Android 11 无线调试界面本身有二维码，但 adb 无扫码接口，需自研 TLS 配对协议——成本过高且易随 ROM 失效）；
- 保存/管理配对码（安全红线，见 §5.2）；
- 跨网段 / VPN / 端口转发场景；
- 需要 root 的 `adbd` 常驻配置。

## 3. 关键需求点与边界条件

### 3.1 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 配对（pair） | `adb pair <ip>:<pairPort> <code>`；前置校验端口为 1–65535、配对码为 6 位数字（Android 11 固定 6 位，仍需允许输入 1–12 位以兼容 ROM 差异） |
| FR-2 | 连接（connect） | `adb connect <ip>:<connectPort>`；结果**靠文本判定**，并区分"已连接"与"新连接" |
| FR-3 | 自动发现 | `adb mdns services` 解析 `_adb-tls-pairing._tcp` / `_adb-tls-connect._tcp`，聚合为同一设备的两端口；点击填充 |
| FR-4 | 断开 | `adb disconnect <ip>:<connectPort>`（修掉现有只传 IP 的问题）；未带端口时退回按 IP 断开全部 |
| FR-5 | 状态与日志 | 全过程状态文本、耗时、失败分类原因；adb 原始 stdout/stderr 进日志区（现状被丢弃，需恢复） |
| FR-6 | 历史与持久化 | 保存最近 IP、配对端口、连接端口三元组（各 10 条）；**不保存配对码** |
| FR-7 | 兼容旧流程 | 保留 `获取 IP` / `启动 adbd(tcpip 5555)` / `connect`；UI 上标明"Android 11 以下请用此方式" |
| FR-8 | 一键连接 | 新「配对并连接」串起 pair→connect→刷新设备，任一阶段失败即停止并给出精确原因（替换现有 `delayMs` 阻塞编排） |

### 3.2 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 响应性 | pair/connect 期间 UI 不冻结（异步），状态区持续显示已耗时 |
| NFR-2 超时 | pair 30 s、connect 40 s（实测不可达 21 s 才返回，留足余量），超时可取消 |
| NFR-3 幂等 | 重复点击不产生并发 adb 调用（现有 `checkAdbRun` 逻辑保留并扩展为状态机锁） |
| NFR-4 安全 | 配对码仅内存使用，不落盘、不写日志、不显示在明文日志区（写日志时打码为 `******`） |
| NFR-5 国际化 | 所有新文案走 `tr()` 并补 `zh_CN/ja_JP/ko_KR/en_US` 四种翻译 |
| NFR-6 可观测 | 关键步骤写主窗日志区（复用 `outLog`），便于用户反馈问题时取证 |

### 3.3 边界条件

| 场景 | 期望处理 |
|---|---|
| Android ≤ 10（无配对概念） | 「配对」按钮禁用并提示改用「USB + 启动 adbd」；仅 `connect` 可用 |
| 配对端口与连接端口混填 | 自动识别：同一 IP 下若 connect 失败且用户填写了两端口，提示"端口可能填反" |
| 配对码错误 | 保留已填 IP/端口，仅清空配对码并聚焦；提示剩余可尝试次数（Android 侧 5 次后失效，不可预知则提示"多次错误请在手机上重新打开无线调试"） |
| 无线调试界面已关闭 | 配对端口立即失效 → 提示"配对端口已过期，请在手机上重新打开无线调试界面并复制新端口" |
| 配对成功、连接端口已变 | 提示"配对成功但连接失败"，提供「重新发现」引导 |
| 同一 IP 多设备（极少） | 以 `ip:port` 为唯一键，不做 IP 去重 |
| 设备休眠断连 | 连接失败按"网络不可达"分类，提示"请确认设备未锁屏休眠" |
| adb server 需要重启 | 检测 `adb version` 失败或 `adb devices` 无响应时给出"重启 adb 服务"按钮 |
| 电脑有多个网卡 / VPN | 提示关闭 VPN 或确认与手机同网段 |
| 已连接同一目标 | `already connected to` 视为成功，不重复报错 |
| 输入非法 | IP 正则校验（IPv4/IPv6/主机名），端口 1–65535，配对码长度校验；非法时按钮置灰 |

## 4. 技术实现方案

### 4.1 整体架构

```
┌─────────────────────────────── QtScrcpy (UI 线程) ───────────────────────────────┐
│ Dialog（无线区域 wirelessGroupBox）                                              │
│   ├─ 输入：IP / 连接端口 / 配对端口 / 配对码 / 发现设备下拉                       │
│   ├─ 按钮：配对并连接 / 断开 / 刷新发现                                          │
│   └─ 状态：QLabel + outEdit 日志                                                 │
│                │ 信号/槽（异步，无 delayMs 阻塞）                                  │
│                ▼                                                                 │
│ WirelessController（新增，QObject，状态机）                                       │
│   states: Idle → Discovering → Pairing → Connecting → Connected | Failed          │
│   职责：参数校验、命令编排、结果解析、超时与取消、错误分类、历史写入               │
└───────────────────────────────┬──────────────────────────────────────────────────┘
                                │ 复用现有单例 adb 通道（串行）
                                ▼
                  qsc::AdbProcess（扩展：超时 / 结果分类 / 取消）
                                │ QProcess → adb.exe
                                ▼
        adb pair / adb connect / adb disconnect / adb mdns services / adb devices
```

**为什么新增 `WirelessController` 而不是继续写在 `Dialog` 里**：现有 `on_wifiConnectBtn_clicked`（`dialog.cpp:1597-1632`）用 `delayMs()` 同步等待 8 步，任一步失败无法中断也无法回滚；新流程是"多阶段 + 依赖上一步结果"的异步链，必须集中到一个状态机里管理，否则 `Dialog` 会进一步膨胀且不可测。

### 4.2 命令契约与结果判定（核心）

| 阶段 | 命令 | 成功判定 | 失败判定 | 提示映射 |
|---|---|---|---|---|
| 发现 | `adb mdns services` | 输出含 `_adb-tls-` 行 | 空列表 / 命令失败 | 空：`未发现设备…` |
| 配对 | `adb pair <ip>:<pairPort> <code>` | 退出码 0 且输出含 `Successfully paired to` | 退出码 ≠ 0 或输出含 `Failed` / `error:` | 见下表 |
| 连接 | `adb connect <ip>:<connectPort>` | 输出含 `connected to <addr>` 或 `already connected to <addr>` | 输出含 `cannot connect to` / `failed to connect` / `unable to connect` | 见下表 |
| 断开 | `adb disconnect <ip>:<connectPort>` | 输出含 `disconnected` | 其余 | 设备离线按成功处理 |
| 校验 | `adb devices` | 目标 serial 出现且状态为 `device` | 未出现 | `连接成功但设备未就绪，请稍后重试` |

**配对错误分类表**（基于 adb 33.0.2 实际文案，实现时以真机回归校准）：

| adb 输出片段 | 含义 | 用户提示 |
|---|---|---|
| `Successfully paired to` | 成功 | — |
| `Failed: Wrong password` / `Failed: incorrect code` | 配对码错误 | 配对码错误，请核对手机上显示的 6 位数字 |
| `Failed: Unable to start pairing client` | 配对端口失效/已被占用 | 配对端口已失效，请在手机上重新打开「无线调试」并复制新端口 |
| `protocol fault (couldn't read status message)` | 端口不可达或非配对服务 | 无法连接配对端口：请确认手机与电脑同一局域网、端口填写正确 |
| `Connection refused` | 端口无服务 | 同上 |
| `adb: usage:` | adb 版本过旧 | 内置 adb 不支持配对，请升级 platform-tools 至 30.0.0+ |
| 超时（30 s 无输出） | 网络不可达 | 连接超时：请检查网段、防火墙、VPN |

### 4.3 AdbProcess 扩展（最小侵入）

现有接口（`include/adbprocess.h:26-44`）保留，仅增两处：

```cpp
// 新增：带超时的执行（内部 waitForFinished(msecs)，超时则 kill 并按失败回调）
void execute(const QString &serial, const QStringList &args, int timeoutMs);
// 新增：结果文本访问（已有 getStdOut/getErrorOut，直接复用，无需新加）
```

要点：

1. **不改异步模型**：`finished` 信号已存在（`adbprocessimpl.cpp:82-90`），控制器用 lambda 回调接续，避免任何 `delayMs` / `waitForFinished` 阻塞 UI 线程；
2. **超时实现**：`execute(..., timeoutMs)` 内部起一次性 `QTimer`，到期 `kill()` 并 emit 失败结果；控制器映射为"超时"分类；
3. **取消**：复用现有 `kill()`（`dialog.cpp:1495-1498` 已在用）；
4. **串行化**：现有单例 `m_adb` + `isRuning()` 已是全局串行，控制器状态机持锁，忙时按钮置灰（替代现有 `checkAdbRun()` 弹日志的做法）；
5. **原始输出透传**：恢复被注释的 `getErrorOut()` 使用（`dialog.cpp:145-150`），把 `connect`/`pair` 的 stdout **脱敏后**写日志区。

### 4.6 关键流程（伪代码）

```cpp
void WirelessController::pairAndConnect(const WirelessTarget &t, const QString &code)
{
    if (!validate(t, code)) { emit failed(QString(), tr("参数不合法")); return; }
    setState(Pairing);
    const QString addr = t.ip + ":" + QString::number(t.pairPort);
    m_adb->execute(QString(), {"pair", addr, code}, 30000, [this, t](bool ok, QString out, QString err) {
        if (!parsePairResult(ok, out, err)) { setState(Failed); emit failed(t.ip, pairErrorText(out, err)); return; }
        emit log(tr("配对成功，正在建立连接…"));
        connectTarget(t);   // 状态 → Connecting
    });
}

void WirelessController::connectTarget(const WirelessTarget &t)
{
    setState(Connecting);
    const QString addr = t.ip + ":" + QString::number(t.connectPort);
    m_adb->execute(QString(), {"connect", addr}, 40000, [this, t, addr](bool, QString out, QString) {
        // 注意：connect 成功/失败退出码都是 0，只能看文本
        if (!out.contains("connected to")) { setState(Failed); emit failed(t.ip, connectErrorText(out)); return; }
        m_adb->execute(QString(), {"devices"}, 10000, [this, t, addr](bool, QString out2, QString) {
            if (!out2.contains(addr)) { setState(Failed); emit failed(t.ip, tr("已连接但设备未就绪")); return; }
            Config::getInstance().saveWirelessTarget(t);
            setState(Connected);
            emit connected(addr);     // Dialog 收到后刷新设备列表、选中该设备
        });
    });
}
```

## 5. 风险、失败场景与处理策略

### 5.1 技术风险

| 风险 | 影响 | 概率 | 处理策略 |
|---|---|---|---|
| 配对端口随无线调试界面关闭立即失效 | 用户复制后操作过慢 → 配对失败 | 高 | 提示文案明确引导"保持该界面打开"；失败后一键回到「刷新发现」 |
| `connect` 失败退出码为 0 | 误报成功 | 确定存在 | **只解析文本判定**（已在 §4.2 固定契约） |
| 不可达时 21 s 黑箱等待 | 用户以为卡死、重复点击 | 高 | 状态区显示"已耗时 Ns"+ 可取消 + 30/40 s 兜底超时 |
| 老 ROM 无线调试端口固定/不可发现 | mDNS 列表为空 | 中 | 保留手动输入四要素；发现失败不阻塞手动流程 |
| 多网卡/VPN 导致 mDNS 与 adb 走不同出口 | 发现到但连不上 | 中 | 提示关闭 VPN；发现结果标注来源网卡（若可解析） |
| adb server 版本冲突（用户装了别处 adb） | 命令行为不一致 | 中 | 启动时固定使用内置 adb 绝对路径（现有 `g_adbPath` 机制已保证）；版本检测失败时提示 |
| `adb pair` 在部分定制 ROM 上被阉割 | 无法配对 | 低 | 错误分类兜底为通用提示 + 引导 USB 老流程 |
| 并发调用 | adb 状态错乱 | 低 | 状态机锁 + 按钮置灰（NFR-3） |

### 5.2 安全风险

| 风险 | 处理 |
|---|---|
| 配对码泄露到日志/配置文件 | 配对码仅内存使用；日志打码 `******`；`WirelessTargets` 不含配对码字段 |
| 配对后任意同网段主机可连 | 属 adb 自身机制，界面提示"仅在与可信设备同网时使用无线调试"（沿用现有风险提示风格） |

### 5.3 失败场景 → 用户可见行为（验收基准）

| 失败场景 | 复现方式 | 期望提示 | 期望状态 |
|---|---|---|---|
| 配对码错误 | 填错 6 位 | 配对码错误，请核对手机上显示的 6 位数字 | Failed，配对码框清空聚焦 |
| 配对端口错/过期 | 填 1 | 配对端口已失效… | Failed，保留其他输入 |
| IP 不可达 | 填 192.168.1.250 | 连接超时…（30 s 后） | Failed，日志有原始输出 |
| 连接端口错 | 配对对的、连接填 1 | 配对成功但连接失败：无法连接连接端口 | Failed，提供「重试连接」 |
| adb 版本过旧 | 换 29.x adb | 内置 adb 不支持配对，请升级 | Failed（启动时预检更佳） |
| 设备休眠 | 手机锁屏后连接 | 网络不可达，请确认设备未锁屏休眠 | Failed |
| 已连接再点连接 | 连两次 | 已连接 IP:port（幂等成功） | Connected 不变 |

### 6.2 真机矩阵（建议）

| 维度 | 覆盖 |
|---|---|
| Android 版本 | 11、12、13、14（`adb pair` 行为一致）+ 10 及以下（仅老流程） |
| ROM | 原生 / MIUI / ColorOS / EMUI（各 1 台） |
| 网络 | 同一 WiFi、双频不同频段、手机热点、开 VPN（负例） |
| 端口 | 首次配对端口、重开无线调试换端口后重连 |

### 6.3 自动化脚本要点（可复用）

```
1) adb pair <不可达IP>:<随机端口> <任意码>      → 断言 21s 内返回、退出码非 0、分类="不可达"
2) adb pair <可达但非配对服务>:<端口> <码>       → 断言分类="端口无服务/协议错误"
3) adb connect <不可达IP>:<端口>                → 断言退出码 0 但输出含 cannot connect → 判定失败
4) adb mdns services                            → 断言空/非空解析不崩溃
5) 真机成功路径：pair 成功 → connect 成功 → adb devices 含 ip:port
```

5. 老流程（USB + 启动 adbd）功能不退化；
6. 全部新文案四语言齐备，中文无英文残留；

# 录制投屏视频时叠加鼠标操作轨迹 — 需求与技术方案

> 日期：2026-11-17　状态：方案评审中（未实施）

## 1. 需求概述

录制投屏视频（`VideoRecorder` → mp4）时，将 PC 端投屏窗口内的鼠标操作（移动、单击、双击、右键、拖拽、滚动）同步叠加到录制视频中：高亮光标、点击波纹、拖拽轨迹线，样式可定制。

## 2. 需要捕获的鼠标事件类型

| 事件 | 捕获点（现有代码） | 用途 |
|---|---|---|
| 移动（悬停） | `VideoForm::mouseMoveEvent`（无按键时不转发设备，本地捕获） | 光标位置平滑插值 |
| 移动（拖拽中） | `mouseMoveEvent`（左键按下，现转发设备） | 轨迹 polyline |
| 按下（左/右/中） | `VideoForm::mousePressEvent`（videoform.cpp:1273） | 波纹生成、按下状态 |
| 释放 | `mouseReleaseEvent`（1322） | 结束拖拽轨迹、终点标记 |
| 双击 | `mouseDoubleClickEvent`（1388） | 双环波纹 |
| 滚轮 | `wheelEvent`（1419） | 滚动方向指示（可选） |

注：中键=Home、右键=Back 的既有映射不影响捕获层（捕获与转发并行）。

## 3. 可视化呈现方式

- **光标**：半透明高亮圆环（默认黄色，白描边，半径约 24 设备像素），位置按最近两次移动事件线性插值平滑；
- **点击波纹**：从按下点扩散的圆环（0→2r，600ms，alpha 1→0）；左键黄、右键红（Back）、中键青（Home）、双击双环；
- **拖拽轨迹**：按下→释放的 polyline，1 秒渐隐尾迹，线宽渐细，释放时终点小圆标记；
- **滚动**：光标旁出现 ↑/↓ 指示 400ms（可选开关）；
- 全部样式（颜色/半径/时长/开关）集中到一个 `TrackStyle` 结构，后续可暴露到设置页。

## 4. 合成层选型对比与决策

| 方案 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 设备端 `showTouch` | adb `settings put system show_touches`，系统触摸点进屏幕流 | 零开发 | 样式固定、无轨迹线、无波纹 | 仅作快速兜底 |
| B. **录制层合成（推荐）** | 在 `VideoRecorder` 编码前 sws 得到的 RGB 帧上用 QPainter 叠加 | 真正进视频、样式可控、复用已有 sws 避免二次转换 | 编码线程 CPU 开销（1080p30 约 3~8ms/帧） | **采用** |
| C. 渲染层叠加 | `QYUVOpenGLWidget` 上盖透明 overlay 实时显示 | 实时预览好看 | **不影响录制视频** | 可选附加（与 B 复用同一绘制函数） |
| D. 轨迹 JSON 旁路 | 录制时同步输出 (ts,event,x,y) 日志 | 录制零开销 | 需后期工序（ffmpeg/Premiere 叠加） | 备选，默认开启低成本 |
| E. 屏幕级录制 | gdigrab/DXGI 录窗口 | 不改代码 | 质量差、遮挡敏感 | 不采用 |

**决策：B 为核心**；C 可选复用；D 默认开启（排查问题与后期合成的兜底）。

## 5. 关键事实（本代码库）

- 录制链路：`Decoder` 解码 → `VideoForm::onFrame`（videoform.cpp:1220）→ 渲染 `updateRender` 与录制 `pushVideoFrame` 两路分支；**帧是解码后的 YUV420P**；
- `VideoRecorder`（recorder/videorecorder.cpp）：内部 `sws_scale` letterbox 到编码尺寸后编码；pts 用本地墙上时钟毫秒（time_base={1,1000}），静止时无新帧不补帧；
- 坐标换算：widget 坐标 ×(frameSize/showSize) 线性映射（QtScrcpyCore inputconvertnormal.cpp:37-58），VideoForm 已按此把事件发给设备；
- 鼠标事件在 UI 线程，onFrame/编码在解码线程。

## 6. 模块职责与数据流

```
VideoForm(UI线程)                       VideoRecorder(编码线程)
 mousePress/Move/Release/DoubleClick      onFrame → pushVideoFrame(YUV)
   └─▶ MouseTrackRecorder                  └─▶ sws_scale → RGB(编码尺寸)
        (坐标换算+QMutex 缓冲)                     └─▶ OverlayProvider 回调
              │                                          └─▶ QPainter 画光标/波纹/轨迹
              └─▶ (可选)轨迹 JSON 追加写文件                     └─▶ 编码 → mp4
```

### 模块拆分

1. **MouseTrackRecorder**（新，QtScrcpy/ui/）
   - 接口：`onMouseEvent(QMouseEvent*, QSize widgetSize, QSize frameSize)`、`onWheelEvent(...)`；
   - 内部：按 `inputconvertnormal` 同款公式把 widget 坐标换算成 frameSize 坐标；维护三类对象——光标位置（带平滑）、波纹列表（出生时间+类型）、轨迹点环形缓冲（1s 窗口）；
   - 线程安全：QMutex 保护，`paintAt(QPainter*, encodeSize, ptsMs, frameSize)` 供合成线程按帧时刻取状态并绘制。
2. **OverlayProvider**（VideoRecorder 新增钩子）
   - `VideoRecorder::setOverlayProvider(std::function<void(QImage &, qint64 ptsMs)>)`；
   - 落点：编码线程在 sws 得到编码尺寸帧后、写入编码器前，wrap 成 QImage（RGB32）调用回调，再写编码器；
   - `VideoForm::startRecord` 装配 provider，`stopRecord` 卸载。
3. **轨迹日志（方案 D）**：MouseTrackRecorder 追加写 `<录像名>.events.json`（`{ts,type,x,y,btn}`，坐标为 frameSize 系），后期可用脚本 + ffmpeg 合成，亦可用于问题对位排查。

### 同步机制

- **统一时钟**：事件与视频帧都用 `QDateTime::currentMSecsSinceEpoch()`（同进程墙钟，误差 <1ms）；波纹动画 age = ptsMs − birth；
- **帧率对齐**：设备流静止时无新帧 → 叠加动画会冻结。对策（按优先级）：
  1. `VideoRecorder` 增加补帧：距上一帧超过 1000/recordFps ms 时用最近一帧重新 push（叠加随新 pts 更新动画）——默认开启；
  2. 不补帧则标注"静止画面波纹停帧"为已知限制；
- **pts 单调化**：沿用 VideoRecorder 现有 `lastVPts+1` 约束，补帧同样受它管。

## 7. 可运行的实现步骤（预计 2.5~3 人日）

1. **MouseTrackRecorder 骨架**（0.5 天）：事件捕获 + 坐标换算 + 波纹/轨迹/光标状态 + QMutex；对位单测：给定事件序列断言绘制内容；
2. **VideoRecorder 叠加钩子**（0.5 天）：`setOverlayProvider` + 补帧 + QImage wrap；验证输出帧尺寸/格式不变；
3. **绘制实现**（1 天）：QPainter 光标/波纹/polyline；渲染层 overlay（方案 C）复用同一绘制函数；
4. **接线与开关**（0.5 天）：ToolForm 录制按钮旁加"录制鼠标轨迹"开关（默认开），startRecord 装配 provider，stop 落盘 events.json；
5. **真机验证**（0.5 天）：录制含单击/拖拽/滚轮的操作 → 播放 mp4 检查波纹与轨迹对位、静止画面动画流畅性（验证补帧）。

## 8. 关键难点与注意事项

1. **双重坐标映射**：事件换算用 frameSize/showSize 线性公式（与设备触控一致）；合成时还要从 frameSize 映射到**编码尺寸**（VideoRecorder 有 letterbox 黑边——需把编码目标矩形暴露给叠加层，否则波纹错位）。最大易错点，实现时先做"四角十字标记"对位验证。
2. **多屏/DPI**：QMouseEvent 给出 widget 本地坐标，天然与多屏 DPI 无关；`getGrabCursorRect` 的 devicePixelRatio 只影响全局鼠标抓取路径，不影响本方案。
3. **线程安全**：事件（UI 线程）与合成（编码线程）并发，必须锁内快照；编码线程不做任何 UI 调用。
4. **帧率对齐/补帧**：见 §6；补帧小幅增加编码负载（静止画面重编码），先直接实现，不足再优化。
5. **性能**：合成复用 VideoRecorder 已有 sws，避免 YUV↔RGB 二次往返；QPainter 软绘 1080p@30 预估 3~8ms/帧；不足时降级为"只画波纹+光标"。
6. **Metal 路径不支持录制**（现状），本功能同样仅覆盖 OpenGL 路径。
7. **轨迹文件隐私**：events.json 含操作坐标，落盘位置与清理策略可配置，不上传。

## 9. 验收清单

- [ ] 录制视频可见高亮光标，位置与实际操作点对位（误差 <1% 画面尺寸）；
- [ ] 单击/双击/右键/中键波纹样式与时长正确；
- [ ] 拖拽轨迹完整，尾迹渐隐自然，释放有终点标记；
- [ ] 静止画面上波纹/轨迹动画不冻结（补帧生效）；
- [ ] 长时间（≥10 分钟）录制无内存增长（波纹/轨迹缓冲正确清理）；
- [ ] 录制文件正常可播（帧率/时间戳无跳变），关闭叠加开关后行为与现状完全一致；
- [ ] events.json 与视频时间轴对齐（抽验 3 个事件）。

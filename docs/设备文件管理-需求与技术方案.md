# 设备文件管理 — 需求文档与技术方案

> 版本：v1.0（2026-11-16）
> 适用项目：QtScrcpy（Windows 桌面端，Qt 5.15 / C++，设备通道基于 adb）
> 参考对标：AnLink「文件」页（左侧功能导航、面包屑路径栏、历史前进/后退、列表化文件视图）

---

## 1. 背景与目标

QtScrcpy 当前已具备投屏、控制、录制、APK 安装等能力（`QtScrcpyCore` 的 `FileHandler` 已实现 push/pull/install 的骨架），但缺少面向用户的设备文件管理界面。本功能目标：

1. 在 PC 端以资源管理器形式浏览 Android 设备文件系统；
2. 支持双向传输（拖拽上传、下载）与轻量编辑（查看/编辑文本并保存回设备）；
3. 提供完整的位置导航能力：刷新、后退/前进历史、上级目录、面包屑跨级跳转；
4. 全程不依赖设备端安装额外 APK，仅依赖 USB 调试授权。

**范围界定**：
- 支持多设备（每个设备会话独立一个文件管理实例，UI 与已连接设备绑定）；
- 首版面向 `/sdcard`（外部存储）为主的普通用户场景；root 场景作为可选增强，不在首版承诺范围内；
- 不做文件删除/重命名/新建目录等写操作以外的破坏性操作（首版仅"上传/下载/编辑保存"三类写操作，降低风险面）。

## 3. 功能需求

### FR-1 浏览设备文件与目录

| 项 | 说明 |
|---|---|
| 触发方式 | ① 连接设备后点击左侧「文件」进入；② 在列表中单击/双击文件夹进入（单击选中、双击进入，与 AnLink 一致采用双击进入 + 单击选中）；③ 面包屑/上级/历史导航间接触发 |
| 交互流程 | 进入页面 → 显示默认根目录（`/sdcard`）→ 异步加载条目 → 列表渲染；再次点击左侧「文件」若窗口已开则置前 |
| 列表内容 | 名称、修改时间、类型（文件夹/常见扩展名分类）、大小；文件夹在前、文件在后，各自按名称排序；提供列头点击排序 |
| 边界与异常 | ① 空目录：显示"此文件夹为空"；② 无权限目录（如部分 `/data` 子目录）：显示"无法访问（权限不足）"，不崩溃；③ 路径不存在（被设备端删除/拔卡）：提示并自动回退到上一个可用目录；④ 符号链接：按其目标类型显示，进入时校验目标存在；⑤ 超长路径/超长文件名：省略号截断 + tooltip 全名；⑥ 大目录（>1000 条）：列表虚拟化，加载期间显示进度，不冻结 UI；⑦ 特殊字符文件名（空格、引号、emoji、换行）：必须原样显示并可操作 |
| 权限与安全 | 默认起始根为 `/sdcard`；对根目录之外的路径可导航但访问失败时给出明确权限提示；设备端无读权限时禁止一切进一步操作（不重试轰炸） |

### FR-2 拖拽上传（PC → 设备）

| 项 | 说明 |
|---|---|
| 触发方式 | 从 Windows 资源管理器/桌面拖拽文件或文件夹到文件列表区域释放 |
| 交互流程 | 拖入时高亮投放目标区 → 释放后弹出传输队列（显示源路径 → 目标路径、总大小）→ 逐项传输并显示单项/总体进度 → 完成 → 自动刷新当前目录 → 完成汇总（成功 N 个 / 失败 M 个，失败项可查看原因） |
| 行为细则 | ① 支持多选与文件夹递归上传（保留相对目录结构）；② 上传目标固定为当前浏览目录；③ 重名冲突：默认询问（覆盖 / 跳过 / 全部覆盖 / 全部跳过）；④ 支持中途取消（取消当前项 + 清空剩余队列） |
| 边界与异常 | ① 本地文件被占用/无读权限：该项失败，其余继续；② 设备存储空间不足：传输前预检（`df` 或错误码映射），给出"空间不足"明确提示；③ 单文件超过 4GB：首版提示不支持并跳过（adb push 对超大文件不稳定）；④ 传输中断开设备：任务标记失败，界面回退为未连接态；⑤ 零字节文件、隐藏文件（`.` 开头）：正常上传 |
| 权限与安全 | 目标目录只读（无写权限）时投放入口禁用并提示；上传路径由 PC 端当前目录决定，禁止把文件写到设备任意路径（防误操作） |

### FR-3 下载文件（设备 → PC）

| 项 | 说明 |
|---|---|
| 触发方式 | ① 右键菜单「下载到…」；② 工具栏「下载」按钮（对选中项生效）；③ 支持多选与整文件夹下载 |
| 交互流程 | 弹出系统"选择保存位置"对话框（记住上次目录）→ 传输进度（速率、已传/总量、剩余时间）→ 完成 → 打开所在文件夹按钮 |
| 行为细则 | ① 重名冲突：默认自动改名（`name (1).ext`），可在设置中改为询问；② 文件夹下载：整体拉取并保留结构；③ 支持取消 |
| 边界与异常 | ① 特殊字符文件名：保存到 PC 时按 Windows 文件名规则清洗（替换 `\/:*?"<>|`），并提示；② 设备端文件在传输中途被删除：报错该项；③ 大文件传输：进度必须可用（不能只有旋转图标）；④ 设备断开：任务失败并提示 |
| 权限与安全 | 仅允许下载当前会话设备；下载目标路径由用户通过系统对话框选择，程序不得静默写入任意系统目录 |

### FR-4 编辑并保存文件内容

| 项 | 说明 |
|---|---|
| 触发方式 | ① 双击文本类文件（按扩展名白名单：`.txt .ini .json .xml .html .css .js .py .java .sh .log .md .csv .prop .conf` 等 + 无扩展名小文件试探）；② 右键菜单「编辑」 |
| 交互流程 | 设备端拉取到本地临时目录 → 打开编辑器窗口（只读/可编辑状态栏：路径、大小、编码、换行符）→ 用户修改 → Ctrl+S 或「保存并回传」→ push 回设备原路径（覆盖）→ 自动刷新列表 → 状态栏提示成功 |
| 行为细则 | ① 保存前若设备端 mtime 已变化（他端修改），提示冲突：覆盖 / 另存为本地；② 支持编码切换（UTF-8 / GBK，默认自动检测 UTF-8 优先）；③ 换行符显示（LF/CRLF），保存保持原换行风格；④ 只读打开：无写权限时进入只读模式并标注 |
| 边界与异常 | ① 非文本/二进制文件（检测到 NUL 字节或超阈值）：提示"二进制文件不支持编辑"，提供「下载」引导；② 大文件：超过 2MB 提示"文件较大，编辑可能卡顿，是否继续？"，超过 10MB 直接引导下载；③ 保存时设备已断开/路径已不存在：内容保留在本地临时副本并提示另存；④ 磁盘临时目录写入失败：明确报错 |
| 权限与安全 | ① 临时文件存放在用户数据目录下独立会话目录（不落系统临时区公共位置）；② 保存回传前二次确认仅在目标为非 `/sdcard` 路径时出现（系统区域风险提示）；③ 编辑器不做任何自动执行/预览渲染（`.html` 仅纯文本展示，防 XSS 类风险） |

### FR-5 刷新当前目录

| 项 | 说明 |
|---|---|
| 触发方式 | ① 工具栏「⟳」按钮；② F5 快捷键；③ 任意写操作（上传/保存）完成后自动刷新 |
| 交互流程 | 重新拉取当前目录条目 → 保持已选中的同名条目选中态 → 排序规则不变 |
| 边界与异常 | 刷新期间再次点击刷新做防抖（忽略重复触发）；当前目录失效时按 FR-1 第 ③ 条回退 |

### FR-6 返回上一步 / 下一步（历史导航）

| 项 | 说明 |
|---|---|
| 触发方式 | 工具栏「←」「→」；鼠标侧键（XBUTTON1/2）；快捷键 Alt+← / Alt+→ |
| 交互流程 | 与浏览器一致：每次"进入新目录"入栈并清空前进栈；后退/前进在历史栈内游走，不重新入栈 |
| 行为细则 | ① 刷新（F5）不产生历史条目；② 历史深度上限 100，超限丢弃最旧；③ 历史条目跨会话不持久化（会话关闭即清空）；④ 按钮不可用态：栈顶/栈底时置灰 |
| 边界与异常 | 目标目录已失效（被删/无权限）：提示并停留在当前目录，历史位置保留（可继续前进/后退跳过失效项） |

### FR-7 跨目录跳转

| 项 | 说明 |
|---|---|
| 触发方式 | ① 面包屑点击任意层级（如 `/` → `sdcard` → `Android`）；② 上级按钮「↑」（逐级返回）；③ 面包屑末尾的「/」点击回到根 |
| 交互流程 | 点击面包屑层级 → 直接加载该目录 → 计入历史栈（与 FR-6 联动） |
| 行为细则 | 面包屑每级显示目录名，路径过长时中间层级折叠为「…」下拉；当前层级高亮不可点 |
| 边界与异常 | 跳转目标无权限/不存在：同 FR-1 异常处理；折叠层级的下拉列表完整展开各级 |

### FR-8 删除（文件/目录）

| 项 | 说明 |
|---|---|
| 触发方式 | 右键菜单「删除」。作用于「选中集合 ∪ 右键所在行」：右键落在已选行上时删除全部选中项，落在未选行上时仅删除该行 |
| 菜单位置 | 独立分组置于菜单底部：「复制路径」下方分隔线之后、「刷新」之前——破坏性操作与信息类操作隔开 |
| 禁用条件 | ① 右键空白处（无条目）不显示删除项；② 条目所在父目录只读时菜单层无法静态判断，由执行时预检兜底：Core 在发出 `rm` 前逐个 `test -w <父目录>`，只读直接返回"权限不足"且不触碰任何文件 |
| 确认弹窗 | 警告图标 + 标题「确认删除」；单选文案「确定要删除"<路径>"吗？目录将被连同其全部内容一起删除，此操作无法撤销。」，多选文案「确定要删除所选的 N 个条目吗？…」并附详细信息区列出全部路径；按钮为「删除」（=Ok）与「取消」（=Cancel），**默认按钮为取消**——回车不会误触发删除 |
| 确认行为 | 执行删除（`rm -rf` 一次删除全部目标），状态栏显示「正在删除 N 个条目…」 |
| 取消行为 | 关闭弹窗，不执行任何操作、不刷新列表 |
| 成功反馈 | 状态栏「删除完成（N 个条目）」+ 自动刷新列表 |
| 失败反馈 | 状态栏「删除失败：<原因>」+ 弹窗显示分类错误（权限不足/不存在/超时等）；仍自动刷新（失败时可能已删除其中一部分） |
| 边界与异常 | 拒绝删除根目录 `/` 与空路径；`rm -rf` 幂等语义——目标已不存在时按成功处理；只读目录先拒绝再执行，杜绝半删状态 |

### 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-1 性能 | 目录 ≤1000 条时加载完成 ≤1.5s（USB 3.0 实测环境）；UI 全程不因 adb 调用阻塞 |

| NFR-5 断连恢复 | 设备会话断开时，文件窗口进入禁用态并提示；重连后刷新可用 |

## 4. 权限与安全要求（汇总）

1. **通道安全**：所有设备交互基于用户已授权的 adb 连接，不请求 root；不申请 Superuser（首版）。
2. **路径校验**：
   - 对用户可达路径做规范化（resolve 符号链接、消解 `..`），防止路径穿越到意外位置；
   - 组装 adb 命令时路径必须作为独立参数传递并做 shell 转义（禁止单字符串拼接），杜绝 `; rm -rf` 类注入；
   - 文件名中的换行/引号等字符不得破坏列表解析协议（见 5.2 的分隔符设计）。
3. **写操作保护**：上传/保存仅允许落在「当前浏览目录」且起始根限定 `/sdcard`；非 `/sdcard` 路径的保存需二次确认。删除操作先预检父目录可写性（`test -w`），只读拒绝执行；拒绝删除根目录 `/` 与空路径。
4. **敏感区域**：进入 `/data`、`/system` 等目录时提示"系统区域，操作可能影响设备稳定性"。
5. **本地数据安全**：编辑临时副本存放于 `%APPDATA%/QtScrcpy/fileEditor/<serial>/`，会话关闭时清理；不将设备文件内容写入日志。
6. **失败安全**：任何 adb 调用必须有超时（默认 10s，传输类按大小放宽）与取消路径；超时不自动无限重试。

## 5. 技术实现方案

### 5.1 总体架构

```
┌─ QtScrcpy (GUI 进程) ──────────────────────────────────────────────┐
│ ui/ FileManagerWindow (QWidget/QMainWindow, 每设备一个实例)        │
│   ├─ FileListModel (QAbstractTableModel, 行数据=DeviceEntry)      │
│   ├─ NavHistory (back/forward 栈)                                 │
│   └─ EditorDialog (QPlainTextEdit)                                │
│ ───────────────── Qt 信号/槽（跨线程 QueuedConnection）─────────────│
│ QtScrcpyCore/src/fileManager/                                     │
│   ├─ FileManager (QObject, 每设备一个；对外信号目录已加载/进度/失败) │
│   │    ├─ RequestQueue (串行任务队列；浏览任务高优先级插队)          │
│   │    ├─ DeviceFileBridge (目录枚举/统计，exec-out 通道)           │
│   │    └─ TransferWorker (push/pull 任务，复用 AdbProcess)          │
│   └─ 复用: AdbProcess / Device(会话生命周期) / outLog             │
└───────────────────────────────────────────────────────────────────┘
```

分层原则：UI 只发"意图"（`FileManager::listDir(path)`、`upload(urls)`…），所有 adb 同步细节在 `QtScrcpyCore` 侧的工作线程完成，结果经信号回 UI——与现有 `Device`/`Server` 的线程模型一致。

### 5.2 通道选型（决策记录）

| 方案 | 说明 | 评估 |
|---|---|---|
| A. 逐条 `adb shell` 命令 | `ls`/`stat`/`push`/`pull` 按需调用 | 实现最简、稳定、复用现有 `AdbProcess`；缺点是每条命令有 adb 进程启动开销（~50-150ms），大目录一次 `ls` 可接受，但**二进制安全**与**文件名特殊字符**需专门处理 |
| B. 自定义 server 协议 | 在 scrcpy server 内扩展文件 socket（类似 control 通道） | 性能最好、可做真流式进度；缺点是需改设备端 jar，升级 scrcpy 版本时冲突维护成本高 |
| C. `exec-out` + 自定义流协议 | PC 端用 `adb exec-out` 跑一段 toybox shell 脚本按自定义分隔符输出 | 兼顾性能与零设备端改动，但脚本健壮性难保证（toybox 版本差异） |

**决策：首版采用方案 A**，协议设计时预留升级到 B 的接口（`DeviceFileBridge` 抽象层，未来在 server 内实现同名能力后仅换实现）。

#### 5.2.1 目录枚举协议（方案 A 的健壮性关键）

直接解析 `ls -l` 文本会因文件名含空格/换行/locale 时间格式而崩溃。采用 **NUL 分隔 + stat 结构化输出**：

```bash
# 一次调用返回目录下全部条目，字段以 \x1f（单元分隔符）分隔，条目以 \x1e（记录分隔符）分隔
adb -s <serial> exec-out \
  "cd '<path>' 2>/dev/null && find . -maxdepth 1 -mindepth 1 -print0 | xargs -0 stat -c '%n%x1f%Fx1f%s%x1f%Yx1e' 2>/dev/null"
```

- `%F` 给出类型（directory/regular file/symbolic link…），无需猜权限位；
- `%Y` 为 epoch 秒，PC 端本地化显示（相对时间规则：<60s 刚刚、<1h N 分钟前、<24h N 小时前、<7d N 天前、超过 7d 显示 `yyyy/M/d`，与 AnLink 一致）；
- 输出按 UTF-8 解码，`%n` 中的 `\x1f/\x1e` 由 find -print0 保证文件名本身不会出现（Android 文件名不允许这些控制符的实际情况仍需 PC 端兜底：解析时若字段数不符则丢弃该条并告警）；
- 无 toybox stat 的老设备（Android <6）回退 `ls -A` + `stat -t` 降级解析。

### 5.3 各功能实现要点

#### 5.3.1 浏览（FR-1）

- `FileManager::listDir(path)`：入队枚举请求 → worker 执行 5.2.1 命令 → 解析为 `QVector<DeviceEntry{ name, type, size, mtimeSec }>` → 信号 `dirLoaded(path, entries)`；
- 排序/过滤在 `FileListModel` 内做（QSortFilterProxyModel 支持列头排序）；
- 失败分类：exit code + stderr 关键字映射为 `NoSuchPath / PermissionDenied / Timeout / DeviceOffline`，UI 呈现对应文案与"返回上一目录"动作。

#### 5.3.2 拖拽上传（FR-2）

- `FileManagerWindow::dragEnterEvent`：校验 `mimeData->hasUrls()` 且设备会话有效才 `acceptProposedAction`；
- `dropEvent`：收集本地路径 → 文件夹用 `QDirIterator` 展开为文件清单（保留相对根）→ 生成 `TransferTask{ localPath, devicePath }` 队列 → 冲突检测（`stat` 目标是否存在）→ 按冲突策略过滤 → 逐项调用 `adb push <local> <device>`；
- 进度：`adb push` 在新版 adb 支持 `ADB_TRACE` 不友好，采用**轮询目标文件大小**（每 300ms `stat -c %s`）估算进度；或对单文件使用 `exec-out` 自实现分块推送（预留优化）；
- 取消：终止当前 `AdbProcess::kill()` + 清空队列 + 删除半成品文件（`rm -f` 目标路径）。

#### 5.3.3 下载（FR-3）

- 多选/文件夹 → 计算总大小（枚举阶段 `du -sb` 或逐项 stat）→ `adb pull <device> <localDir>` 逐项执行；
- 进度同 5.3.2（轮询本地增长大小，pull 场景轮询本地文件更精确）；
- 文件名清洗：Windows 非法字符替换为 `_`，冲突自动加序号。

#### 5.3.4 编辑保存（FR-4）

```
双击文本文件
  → transferWorker: adb pull 设备文件 → %APPDATA%/QtScrcpy/fileEditor/<serial>/<hash>.<name>
  → 编码探测：BOM > UTF-8 校验 > GBK 兜底；NUL 字节出现即判二进制拒绝
  → EditorDialog 加载（QPlainTextEdit，等宽字体）
  → 保存：写本地副本 → adb push 回原路径（临时名 + mv 原子覆盖，避免写一半中断留下半文件）
  → 刷新目录 + 清理临时副本
```

- 冲突检测：编辑窗口打开时记录设备端 mtime，保存前重新 `stat`，不一致则弹冲突选择；
- 原子回传细节：push 到 `<path>.qtscrcpy.tmp` → `mv -f tmp <path>`；`mv` 失败时保留 tmp 并报错，不覆盖原文件。

#### 5.3.5 刷新 / 历史导航 / 跨目录跳转（FR-5/6/7）

- `NavHistory`：`QVector<QString> m_stack; int m_pos;`——`navigate(path)` 截断 `m_pos` 之后并追加；`goBack()/goForward()` 移动 `m_pos` 后调用 `listDir`（入栈标志置 false）；`m_pos` 边界决定按钮 enabled 态；历史去重（连续相同路径不入栈）；
- 面包屑：`path` 按 `/` 切分，`QToolButton` 链 + QHBoxScrolledArea；折叠规则：可见宽度不足时保留首（根）与末两级，中间收进「…」菜单；
- 刷新防抖：`listDir` 进行中收到新请求，若 `path` 相同且 `force=false` 则忽略；`F5` 用 `force=true`。

### 5.4 线程与队列模型

- `RequestQueue`：单设备串行；两个优先级——`Browse`（立即执行）与 `Transfer`（FIFO）；正在执行的 `AdbProcess` 不可抢占，浏览请求等当前命令结束（≤10s 超时）后插队执行；
- 所有 `AdbProcess` 在 worker `QThread` 中创建与销毁，避免现有 GUI 线程启动 adb 进程的偶发卡顿；结果统一 `QueuedConnection` 回 UI 线程；
- 会话断开（`Device::serverStoped` / adb devices 无该序列号）→ `FileManager::onDeviceGone()`：kill 全部活动进程、清空队列、UI 置灰。

### 5.5 与现有代码的衔接

| 现有组件 | 复用方式 |
|---|---|
| `AdbProcess`（`adbprocessimpl.cpp`） | 直接复用 `execute(serial, args)` 与 `AER_*` 结果信号；需补充：超时参数、`exec-out` 支持确认、stderr 捕获细化 |
| `FileHandler` | 现有 push/pull 骨架迁移进 `TransferWorker`，把"安装 APK"等既有功能与新的传输队列合并到同一串行队列，避免并发 adb push 冲突 |
| `Device` / `IDeviceManage` | `FileManager` 由 `Device` 持有（与 `Decoder`/`Controller` 同级），随会话生灭；`FileManagerWindow` 在 `Dialog::onDeviceConnected(true)` 时创建 |
| `outLog` / i18n | 日志与文案复用现有机制 |
| 配置 | `userdata.ini` 新增：下载目录记忆、重名策略、编辑器字体、大小警告阈值 |

### 5.6 测试要点（验收清单摘录）

1. 含空格/引号/emoji/中文文件名的目录枚举、上传、下载、编辑全链路；
2. 1000+ 条目目录加载不卡 UI、列头排序正确；
3. 传输中途拔线：UI 不卡死、无残留半成品（上传场景目标 tmp 文件被清理）、错误可读；
4. 权限不足目录（未授权存储的老设备）浏览与上传的提示正确、可返回；
5. 编辑保存的原子性：保存过程中断电/拔线，设备端原文件未被破坏（验证 tmp+mv 方案）；
6. Alt+←/→、鼠标侧键、面包屑跳转与历史栈一致性；
7. 两台设备同时打开文件窗口互不串扰（serial 隔离）。
